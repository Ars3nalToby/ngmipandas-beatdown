# NGMI Pandas — working notes

Single-file game: `index.html` (React 18 UMD + Babel standalone + Three.js r149 + MQTT). No build step. Deployed by Vercel from `main` (https://ngmipandas-beatdown.vercel.app/). Push to `main` = live.

## Map of index.html (grep these names; line numbers drift)

- **Shootout design rules live in `SHOOTOUT_DESIGN.md`. Read it before changing Shootout; its section 2 rules are hard rules.**

- `MATCH_SECONDS` (Beatdown clock) and `SHOOT_SECONDS` (Shootout clock): top of the script.
- Audio: `sfx` object (cases like `'call'`, `'dash'`, `'cannon'`), music via `musicTimer`, `kickAudio` global listeners. Music buses: `musicBus` (drums) / `harmBus` (bass+pads, ducked by `duck()` on every kick) / `leadBus` (arps, leads, bells; feeds the echo) → `musicMix` → shared convolver reverb. Themes: `main` (lobby/Beatdown, `TRACKS`), `shootout` (`STRACKS`, `SRUSH`), `zombie` (`ZTRACKS`, `ZRUSH`). Helpers `kick/snare/hat/tom/voice/riser`; beat themes go through `scheduleBeat`, zombie through `scheduleHorror`. Keep node creation per step modest (phones). `sfx.setLoad(bool)` (set from the zombie frame loop: >14 zombies or `perf.slow`) switches music to busy-fight mode (quieter, dry, no leads/detuned layers) and `play()` has a voice budget per 60 ms (`SFX_KEEP` sounds always pass).
- Story: `CHAPTERS` (5 entries, each with `mode`, `check(s)`, `intro`, `outro`), `storyEval(idx, st)`, `StoryComic`, `StoryResult`, `STORY_PROLOGUE`, `STORY_EPILOGUE`.
- Profile: `defaultProfile`, `loadProfile`, `saveProfile`, `awardXp`, key `PROFILE_KEY` (localStorage `ngmi_profile_v1`).
- Lobby: `App` component (screens: lobby, playing, shootout). `LobbyBackdrop`, `Showcase`, `ClipGallery`.
- Shootout: `ShootoutGame`. Match init `const match = { left: SHOOT_SECONDS ...}`, `endMatch`. Variants: `ffa`, `siege`, `zombie` (lobby `soVariant`; zombie sub-mode `soZMode` = `raid` | `incoming`, passed as `zmode`).
- Weapons: pickup rules are `WEAPON_RANK` + `addWeapon` (rank-based, RPG is sticky, 2nd RPG = dual via `w.dual`, `weaponMag(w)` = real magazine size); `SHOOT_WEAPONS` (incl. `sniper` with `pierce`, `flamer` with `flame`/`range`, `revolver`), pickups `SHOOT_PICKUPS`, models in `makeGunModel`.
- Shootout melee/shove/graze: `SHOOT_WEAPONS[*].melee`, `SHOVE`, `meleeStrike`/`swingMelee`/`doShove` (before `fireMe`), `traceShot().graze`, `me.shots/hits/bloom`, zombie `stunT` (knock array 3rd element, net field `ks`). Right click = shove, ADS = hold Z. Explosion ring/glow come from `boomPool`; bullet holes from `bulletHole` pool. Any new pooled FX must follow SHOOTOUT_DESIGN.md.
- Zombie mode: constants `ZOMBIE_KINDS`, `ZKIND_IDS`, `ZOMBIE_RAID_WAVES`, mesh `buildZombieMesh` (shared geometry, pooled per kind). Inside `ShootoutGame` search `ZOMBIES: the host runs the horde`: `zd` director state (phases `boot/prep/wave/clear/over/won`, horde 0–3), `zTick` (host only), `updateZombie` (host AI), `animZombies` (everyone), `hurtZombie` → `applyZDamage` → `killZombie`, boss `bossAct`/`throwRock`/`slamFx`, `bloaterPop`. Downed/revive: `goDown`, `tickDowned`, `reviveFighter` (owner-side: you on your client, bots on the host). Net: host packet carries `zs`/`zd`/`zfx`; clients send `zh` (damage), host sends `zk` (kill + credit); `dw`/`rv` on player packets. Zombie rooms use their own MQTT topic (`.../shootout/v1/zombie/ROOM`). Squad is capped at 4 (bots retire as friends join).
- Zombie map: `buildShootoutMap(scene, cinematic, zmap)` — with `zmap` the perimeter grows to ±86, six buildings become walk-ins (`WALK` table) and six new outskirts buildings are added via `walkIn(...)`. It returns `rooms`/`portals` (door graph used by `navStep`/`regionOf`), `ladders` and `zspawns`. Colliders can be switched off with `c.off` (barrels); `moveBody` stops heads at ceilings.
- Call the office (zombie only, key B / 📞 button): `callOffice` + `tickOffices` — 3.2 s radio delay, then 10 dynamite sticks fall along the aim line (30 m) and call `explodeAt` (scale 0.85); sticks never explode within 6 m of any living squad member; 60 s cooldown (`me.dynCd`, HUD `office`).
- Delta Force (zombie, fictional operators): host calls `callDelta` when `zd.teamKills >= zd.deltaAt` (45, then +70+10n) → zfx `[4,x0,z0,x1,z1]` → every client runs `startDelta`/`tickDelta` (scripted sweep in/hold 10 s/out, 4 ops, identical on all screens); only the host calls `hurtZombie` (src id `delta`, doesn't count as team kills). Takedown <2.7 m = 1800 dmg (boss 120). Squad bots: dmg scales +17%/wave, shorter bursts, resupply nades each wave.
- Layered onboarding (zombie): `showTip(id,text)` + `coach` queue (one tip at a time, each shown once, saved in localStorage `ngmi_tips_v1`) triggered in the zombie HUD block; touch ✋ shows after the shove tip/wave 3, 📞 after the office tip/wave 4 (`hud.ushove/uoffice`). Add `?fps=1` to the URL (or localStorage `ngmi_fps`=1) for an fps + zombie-count chip. Delta/dynamite auto-save a clip 7–9 s after they start. New features should get a tip + a wave they unlock at, not a new always-on button.
- Look upgrades (2026-10-26): zombie kit has sockets/dead eyes/teeth/claws/ribs/torn hem and `skinZombie` bakes grime (mottling, ground darkening, stains) into vertex colours; `srgbTex` sets anisotropy 8; the post shader has an unsharp mask, less chromatic aberration and half the grain; touch pixel-ratio cap 1.7 (adaptive resolution drops it). Explosions are occluded by walls (`walled()` in `explodeAt`, 20 % damage), dynamite lands on roofs (`gy`).
- Fresh start every visit (2026-10-26, owner's request): a block at the top of the babel script wipes every `ngmi_*` localStorage key (except `ngmi_fps`, `ngmi_a2hs_off`) and the `ngmi_clips` IndexedDB on EVERY page load. So profile, XP, tips, name/room, story progress and clips never survive a reload. Delete that block to restore saving.
- Art pass 2 (2026-10-26): zombie body is a hunched human frame (leaning capsule torso, pelvis, neck, two-segment arms with elbow/hand, thigh+shin+foot legs; bloater keeps the round body). AK viewmodel rebuilt with cylinders (barrel, gas tube, muzzle brake, sights, banana mag, wood furniture). Walk-in buildings get cosmetic roof clutter (AC units, vent, antenna; no collision). `ZSTORY` = one radio line per raid wave, shown through `showTip` at wave prep; PaperHands = the Rug Lord (Chapter 5 outro and epilogue now point to the Zombie Raid).
- Horror pass (2026-10-26): zombies are gaunt/hollow-eyed (no cute pandas): skull head, black eye hollows, hanging jaw, exposed skull, long arms. Stats buffed (walker 4.3–5.7, runner 8.8–10.2, brute 680 hp); runners pounce (`zz.lungeT`). Squad bots: speed 8.4, shove (`botShove`), kite brutes/bloaters but stand against runners, retreat to the leader under 38 hp, reload while idle, and radio the office themselves (`botOfficeTick`, host only, zfx 5 announces) for packs of 8–11 clear of the squad.
- Zombie extras inside `ShootoutGame`: corpses (`toCorpse`, pooled meshes), `gibFx`, `splat` decals, spitter acid (`acids`, `throwRock(..., 'spit')`), grenades/medkits (`doThrow`, `throwables`, net `th`/`mkx`/`heal`), explosive barrels (`barrels`, `detonateBarrel`, net `bx`), callouts (`callout`, `CALLS`, speech via `voiceRef`, packet `cl`), hold-fire revive (`me.revTo`, packet `rt`), squad AI `updateSquadBot` (teamwork: `b.mate` = designated reviver, `b.cover` = covers a revive, `planMedRun` = medic+escort medkit fetch, `focus` map = focus fire, spacing push), minimap `drawMini` (canvas `miniRef`), bottomless mags `world.frenzyT`. Raid = `ZOMBIE_RAID_WAVES` (10), bosses on waves divisible by 5.
- Audio: `sfx.play(name, vol, p, pan, muffle)` routes through a stereo panner + lowpass when `pan`/`muffle` are given (`curBus`). In `ShootoutGame` use `play3d(name, pos, vol, pitch, range, occlude)` / `spatial(pos)`. Zombie sounds: `zStep` (footsteps synced to the walk cycle, budget 4/frame), `zbreath`, `zswipe`, `hordeRumble` from `zd.hordeAt`. Music has themes: `sfx.startMusic('zombie')` plays `ZTRACKS`/`ZRUSH` via `scheduleHorror`; everything else uses the original `TRACKS`. Zombie mode drives `sfx.setIntensity` from the nearest zombie.
- Zombie pathing (host only): `FF` is a 1 m flow-field grid over the whole zombie map (walls padded 0.8 m, things you can step over or walk under ignored). `tickFlow` floods it outward from every survivor in slices of 3,500 cells per frame into a back buffer (about 0.1 ms per frame), rebuilt every 0.25 s; survivors on a roof seed the nearest ladder foot. `flowWp` gives each zombie a point 3 cells downhill (or null = walk straight at the target). `navStep`/rooms/portals are still used by squad bots. Non-boss zombie body radius is capped at 0.75 so brutes fit through 2.8 m doors.
- A wave can never stall: per-zombie watchdog (`noProg`, 15 s without closing in → `relocateZombie` to an unseen spot 16–26 m from its target, rising out of the ground); when ≤3 zombies remain after all spawns, `huntOn()` marks them for everyone (🧟 screen markers + pulsing minimap rings clamped to the edge); at `zd.stragT` > 18 s far ones are brought in every 8 s, at > 75 s non-boss stragglers collapse. Guests snap a zombie that moved > 10 m instead of sliding.
- Level rule: never put props in a doorway lane (the chemist counters once sealed both doors). After editing the zombie map, run a reachability check: flood `FF` from (0,0) and confirm every room, zspawn and pickup is reachable.
- Litter (zombie map, cosmetic, local only): `LITTER` kinds as InstancedMesh, `tickLitter` kicks items when players/zombies walk through (`kickT` cooldown).
- Beatdown: effect inside `App` with `const match = { left: MATCH_SECONDS ...}`. Gang logic: `addMinionToFighter`, `spawnWildPanda`, `wildMinions`. Moves: `doDash`, `fireCannon`, `startTornado`, `doSmash`. Action flags: `actionTriggerRef.current.{jump,smash,dash,cannon,ult}`. SMASH/DASH/THROW go through an input buffer (`pressBuf`, `INPUT_BUFFER_MS`) so a tap stays live for ~0.3 s. The `call` and `swarm` flags are dead code.
- GPU memory: gang/wild panda meshes come from `takePanda` and go back with `releasePanda` (pooled). Use `disposeObj` for anything else you remove from the scene.
- Multiplayer (Beatdown): `ROOM_SLOTS` = 8 fighters; humans first, the host (smallest peer id) fills the rest with bots via `botsWanted` and retires bots as friends join. `livePeers()` = peers seen in the last 5 s. The MQTT client is kept across rounds (`client.__topic`, `onNetMessage` swapped per round) and closed when leaving the playing screen. Party matches (`results.party`) auto-start the next round after 12 s (`nextRound`). Lobby presence: `useRoomPresence`; shared loader `loadMqtt`, broker `MQTT_URL`. Name and room are saved in localStorage (`ngmi_name`, `ngmi_room`).
- Multiplayer testing: run a local aedes broker over ws, point `MQTT_URL` at it in a test copy, and gate `renderer.render` behind a flag so several pages run at real speed.
- Network input is untrusted: clamp numbers with `netNum`, room codes with `cleanRoom`. Story chapters never connect to MQTT (`storyMode`).
- Beatdown PUNCH→GRAB (2026-10-26): the PUNCH button turns into GRAB for 3.5 s after a landed haymaker (`f.grabT`, `cooldowns.grab`, `doGrab`), then reverts; no extra button. `doPunch` (key F/J, touch 👊 button, `cdState.punch`, `CD_MAX.punch`): aimed jab/cross/haymaker combo (`f.punchStep`/`punchT`, 3rd hit launches), auto-aims at the nearest rival in a cone, net event `punch`. `launch()` now gives the LOCAL attacker feedback (damage % sprite, `fx.hitStop`, buzz); `fx.hitStop` really slows `dt` now. Touch buttons answer a tap on cooldown with a shake + sound (`.act-btn.denied`); dash works while tumbling; input buffers are 260-450 ms.
- Mobile controls: the `[ {key:'jump'...}, {key:'smash'...} ]` array in the action cluster, plus the floating joystick and `releaseJoy()`.
- Desktop ability cards: the array with `keyLabel` (E, SHIFT, C, T).
- Clips: `createClipper`, `clipDB` (IndexedDB `ngmi_clips`), `clipStore`, `shareClip`, `downloadClip`.
- Results screens: Beatdown and Shootout results cards near the bottom of the JSX. Buttons: PLAY AGAIN, LOBBY.

## Rules for working here

- Performance rules (keep the game smooth on phones):
  - Canvas textures go through `cachedTex` (`makeGlowTexture`, `createLabelTexture`, `makeEmojiTexture`, `makeSuitTexture` are memoised and marked `userData.shared`); never build one per frame or per particle. `disposeObj` skips shared textures/geometry/materials.
  - Pandas: `buildNgmiPandaMesh` builds each kind once (`PANDA_TEMPLATES`, real work in `buildPandaFresh`) and returns clones sharing geometry+materials. Don't mutate a panda's materials per instance; add your own material if you need per-panda colour changes.
  - Static parts are baked with `mergeStaticParts(root)` (models) and `mergeSceneStatic(scene, keepRefs)` (Shootout/Siege maps). Anything you animate later must be referenced from `root.userData` / the keep list, or it gets baked. Map originals stay detached in `solids` for raycasts.
  - Shootout FX: `spawnFx` and `puff`/`takePart` are pooled (no new materials mid-fight). Collisions use the uniform grid `nearColliders(x0,x1,z0,z1)`; don't loop over all `colliders` in per-frame code.
  - Both games use adaptive resolution (`perf`/`setPR`). React state set from game loops must only change when values change (see `setCooldowns`/`setBuffHud`).
  - FLIPSIDE art (2026-10-28, owner's choice; see SHOOTOUT_DESIGN.md §6): `FLIP_ART` (off with `?art=classic`). `flipShaders(true/false)` patches/restores `THREE.ShaderChunk` lighting (cel step, no specular, hatching) at Shootout mount/unmount, so never compile Beatdown materials while it's on. `surfTex` returns `flipSurfTex` (flat paint + ink lines, hex `pavement`); `mergeSceneStatic` pulls map colours to `FLIP_PAL` (`flipHex`), skips fake AO and builds ONE ink `LineSegments` from every Box/Plane; `flipShadowMesh` bakes flat navy cast shadows from `colliders` (stencil so overlaps don't double up) instead of contact shadows/shadow maps; `addInk(root, t)` adds outline shells (merged per animated group; skinned hull for zombies; scaled silhouette for the viewmodel), run by `inkPass` every 15 frames on scene children with `rightArmGroup` / bone `head`. HUD theme = `.so-flip` CSS block (overrides Tailwind colours/radii) + `.flip-banner` call-outs numbered by `FLIP_N`.
  - (Classic look only) Town materials are realistic, not cartoon: `surfTex(kind)` draws seamless canvas textures once (brick, render, block, metal, roof, asphalt, pavement, tiles, wood; `SURF_TILE` = metres per tile) and `facadeTex` draws windows/doors. Inside `buildShootoutMap`, `surf(kind, tint)` returns cached materials flagged `userData.tile`; `box()` then rewrites UVs in metres (`worldUV`), and `colorBakes` lets those mapped materials bake their tint into vertex colours, so every brick wall is one draw call. Each building's facade comes from `FACADE[label]`. Black edge outlines are opt-in only (`o.edge`); keep them off (FLIPSIDE draws its own merged ink edges).
  - Zombies are ONE skinned mesh each (`skinZombie`): all non-glowing parts are baked into a SkinnedMesh with 6 rigid bones (root, head, 2 arms, 2 legs), and glowing bits (eyes, warts, gold) ride on the bones. `userData.head/arms/legs` are Bones, so animation code just rotates them. Bones can't be hidden: headshot corpses and legless crawlers use `scale.setScalar(0.001)`. About 2 draw calls per zombie (was 8).
  - Horde limits: overflow during the horde is ZMAX+4 on touch and ZMAX+10 on desktop. Corpses are capped at 10/16, dropping to 5/8 when the fight is busy, and sink after 3.2 s. Blood splats are one InstancedMesh (`splatInst`, 40/64 ring). Zombie separation radius is 0.5×(s1+s2). With more than 20 zombies the host sends `zs` every other packet; guests handle packets without `zs` (`applyZState` returns early after the phase/horde part).
  - Highlight recorder (`createClipper`) copies the screen at about 24 fps on touch (720p) and 33 fps on desktop, and at 10 fps while `perf.slow` (the game averaging under 42 fps). Benchmarks should set `window.__CLIP = false` (mk.py gates it) or the software GPU's readback dominates.
  - Look/realism is faked cheaply, never with real-time shadows or extra lights: `bakeMeshes(..., ao=true)` darkens map vertices near the ground (fake AO, baked once); contact shadows under colliders use `softRectTex` quads baked into the merged map; characters get blob shadows from one InstancedMesh (`updateBlobs`); zombie night adds lamp pools/cones/bulbs (`map.lamps`), lit windows (`winLit`), a vertex-colour sky dome + stars; first-person gun reflects a tiny PMREM env (`GUN_ENV`, viewmodel only); strafe camera roll (`me.roll`); CSS vignette over the canvas.
  - Benchmark recipe: wrap the loop (`loopInner`/`animateInner`) to push per-frame ms into `window.__perf`, gate rendering behind `window.__RENDER`, and count visible objects; compare against `git show HEAD:index.html`.

- Work directly on `main` and push when done (owner's standing preference: no feature branches, he tests on the live site). Run the compile check and a browser smoke test first, since push = live.

- Compile check before pushing: extract the `<script type="text/babel">` block and run `@babel/standalone` `transform` with the `react` preset.
- Browser tests use Playwright with `/opt/pw-browsers/chromium` and CDN routing to `/tmp/bchk/node_modules`. Rendering is about 1 fps in the sandbox, so shorten clocks in a test copy rather than waiting for real match lengths.
- Never run the full game without a timeout. Run long tests in the background and poll their log.
- Keep dev notes and test artefacts out of the repo. Use the session scratchpad.
- Commit messages end with the attribution lines the session asks for.

## Known open items

- Real-device feel for dash, tornado, throw and the joystick is not verified.
- Gang growth was tuned down (9 starting grey pandas, pickup radius 2.6, Tornado tops up to 5). Needs real-play feedback.
- iPhone has no vibration API, so `buzz()` only works on Android.
- Story chapters 2–4 are Beatdown-only by design. Shootout is deferred until mobile shooting feels fun.
- Zombie mode balance (wave sizes, boss HP, horde size) is only bot-tested. Needs real squad feedback, especially on phones (zombie cap `ZMAX` is 16 on touch, 26 on desktop).
